# Kidswear Margin Reset: proof of concept and feature roadmap

A working pipeline for retail margin decisions in a fashion department, built in five iterations:
demand forecasting on censored sales, size curves, markdown optimisation, quality-gap detection,
store trials and the controls that keep the models honest. It runs on realistic synthetic sample
data and is designed to take real extracts through the same data contracts.

The planner app built from these results is published at
[ai-university.co.in/kidswear-planner.html](https://ai-university.co.in/kidswear-planner.html).

## Run it

```bash
pip install -r requirements.txt
FRESH=1 bash run_all.sh        # ~12 minutes: Kidswear end to end, Babywear core, planner app, tests
python3 tests/test_pipeline.py # unit + integration checks
python3 retrain.py status      # retraining policy and current signals
```

Run any single step for another department with `DEPT=babywear python3 05_demand_forecast.py`.
Data and models are regenerated by the pipeline (fixed seeds) and are not committed.

## Splits and honesty rules

* Time-based split: train week_index 1-90, validation 91-97, test 98-104 (FY2026 winter clearance), scored once.
* Every lagged input is at least 8 weeks old.
* `data/<dept>/raw/ground_truth/` holds the simulator's hidden truth. It is used only to score results, never to train.
  On real data, the markdown and allocation scoring is replaced by the store trial.
* Markdown plans are compared at the same sell-through as today's plan, not at a convenient target.

## What could not run here

* Foundation models: the Chronos and TimesFM adapters are written and tested for graceful failure, but the
  model weights could not be downloaded in the build environment, so transparent zero-shot fallbacks were used.
  Set `CHRONOS_MODEL_PATH` and install `torch` + `chronos-forecasting` to switch them on.
* Live external feeds and source systems: the weather, events, competitor and macro feeds and the POS/ERP extracts
  are generated in the documented formats; point the adapters at real exports via `config/source_mappings.json`.
* The scheduled retraining workflow is switched off while the data is synthetic (see the workflow file).

## Moving to real data

Replace `01_generate_data.py` with extracts in the contract formats (or source-system exports plus mappings),
run `02_validate_data.py` until it passes, then the rest of the pipeline unchanged. Steps that score against
ground truth (`08`, `10`, `11`, `13`) switch to observed outcomes and the trial readout.
